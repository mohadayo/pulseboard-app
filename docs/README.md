# ドキュメント（`docs/`）インデックス

このディレクトリには、リポジトリルート [`README.md`](../README.md) では触れきれない設計・運用の詳細ドキュメントを配置しています。PulseBoard は Python API・Go ワーカー・TypeScript BFF の 3 サービスで構成されるため、サービス横断で参照するドキュメントは本ディレクトリに集約しています。

## 目的別インデックス

### 全体像を把握したい

- **[architecture.md](./architecture.md)** — 3 サービス（Python API / Go ワーカー / TypeScript BFF）の責務、サービス間通信、データフロー、コンテナ構成を整理したドキュメント。「どこを触るとどこに影響するか」を掴みたい時の起点。

### 設定・運用

- **[CONFIGURATION.md](./CONFIGURATION.md)** — 環境変数・設定ファイル・シークレット管理など、各サービスをどう設定するかのリファレンス。ローカル開発・ステージング・本番で切り替える必要のあるパラメータを一覧化。
- **[RUNBOOK.md](./RUNBOOK.md)** — 起動・停止・再起動、Docker Compose での立ち上げ、デプロイ手順など、想定される定常運用手順を集約した実行手順書。

### 障害対応・切り分け

- **[FAQ.md](./FAQ.md)** — 「ダッシュボードにデータが反映されない」「認証エラーが出る」など、開発者・利用者からよく寄せられる質問への回答集。
- **[TROUBLESHOOTING.md](./TROUBLESHOOTING.md)** — 「サービス間通信が失敗する」「ワーカーがキューを処理しない」など、発生しがちな不具合とその切り分け手順・対処法。

## その他のリファレンス

## ドキュメントを追加・更新する時のガイド

- 新しく `docs/` にドキュメントを追加した場合は、本ファイルの該当セクション（全体像 / 設定・運用 / 障害対応・切り分け）に 1〜2 行の説明と共にエントリを追加してください。
- リンクは可能な限り **リポジトリ内相対パス** で書いてください。相対パスは GitHub 上でも `git clone` 後のローカルビューでも同じように解決でき、リポジトリ移設や rename の影響を受けにくくなります。
- ドキュメント本文の記述スタイル（見出しレベル・箇条書き・注記の書式）は既存ドキュメントに合わせてください。
- サービス固有の詳細（例: `services/<service-name>/` 特有の設定手順など）は、そのサービスのディレクトリ配下に README を置くほうがオーナーシップが明確になります。ここに集約すべきなのは、複数サービスを横断する視点のドキュメントです。
