# 集計統計量リファレンス

`metrics-worker` の `POST /api/v1/aggregate` が返す各統計量について、
**定義式・母集団/標本の別・縮退時（単一/定数/空入力）の挙動・実務での使い分け** を
まとめたリファレンスです。API レスポンス JSON の各フィールド名は
本ドキュメントの見出しと 1 対 1 で対応します。

- ソース: [`services/metrics-worker/main.go`](../services/metrics-worker/main.go)
- 呼び出し例と上限値: リポジトリルート [`README.md` › Metrics Worker](../README.md#metrics-worker-8001)

以下、値集合を `x = (x₁, x₂, …, xₙ)`、その要素数を `n = count`、
昇順ソート済み系列を `x₍₁₎ ≤ x₍₂₎ ≤ … ≤ x₍ₙ₎` と表記します。

---

## 前提: 入力バリデーションと縮退時の挙動

- `values` は空でない配列でなければならない（空配列は `400`）。
- 各要素は有限な数値のみ許容。`NaN` / `±Infinity` は `400`。
- `values` の要素数は `MAX_AGGREGATE_VALUES`（既定 `10000`）を超えると `413`。
- リクエストボディ全体は `MAX_AGGREGATE_BODY_BYTES`（既定 1 MiB）を超えると `413`。

したがって以降の「空入力での挙動」欄は、内部での再利用や関数単位テスト時の想定であり、
公開 API から到達する経路では常に `n ≥ 1` である点に注意してください。

---

## 1. 基本統計量

### `count`

- 定義: `n`
- 縮退: 単一 = 1、定数 = n、空 = 0

### `sum`

- 定義: `Σ xᵢ`
- 縮退: 単一 = `x₁`、定数 = `n·c`、空 = 0

### `min` / `max`

- 定義: それぞれ `x₍₁₎`, `x₍ₙ₎`
- 縮退: 単一 = `x₁`、定数 = `c`

### `range`

- 定義: `max − min`
- 縮退: 単一 = 0、定数 = 0

### `avg` (算術平均)

- 定義: `μ = (Σ xᵢ) / n`
- 縮退: 単一 = `x₁`、定数 = `c`

### `median` (= `p50`)

- 定義: 線形補間による中央値。線形補間の詳細は §3 [分位点] を参照
- 縮退: 単一 = `x₁`、定数 = `c`

---

## 2. 広がり（scale / dispersion）

### `variance` (母分散)

- 定義: `σ² = (1/n) · Σ (xᵢ − μ)²`
- **母集団版** を採用（分母は `n`、標本分散の `n−1` ではない）。
- 縮退: 単一 = 0、定数 = 0

### `std_dev` (母標準偏差)

- 定義: `σ = √variance`
- 単位が入力値と一致するため、`variance` より解釈しやすい。
- 縮退: 単一 = 0、定数 = 0
- 外れ値の影響: 二乗和のため大きく引きずられる。頑健版として `mad` を参照。

### `cv` (変動係数, coefficient of variation)

- 定義: `cv = std_dev / avg`（`avg ≠ 0` のとき）
- 意味: スケール正規化された相対的ばらつき。系列同士（例: レイテンシ vs スループット）を
  同一軸で比較する際に有用。
- 縮退・注意点:
  - `avg = 0` の場合は 0 を返す（ゼロ除算回避のガード）。
  - 単一・定数入力では `std_dev = 0` のため `cv = 0`。
  - 正負が混在し `avg` が符号反転する系列では **解釈が破綻** する。CV は
    「非負・単位が意味を持つ量」（レイテンシ、リクエスト数、CPU 使用率など）に限って使う。

### `iqr` (四分位範囲)

- 定義: `iqr = p75 − p25`
- 意味: 中央 50% の値がどれくらいの幅に収まっているか。`range` と違い両端の外れ値の影響を受けない。
- 縮退: 単一 = 0、定数 = 0

### `mad` (中央絶対偏差, median absolute deviation)

- 定義: `mad = median(|xᵢ − median(x)|)`
- 意味: `std_dev` の **頑健版**。極端な外れ値に引きずられず、中央部の代表的なばらつきを保つ。
- 縮退: 単一 = 0、定数 = 0
- 実装上の注意: 一般に `mad` を正規分布下の `std_dev` と揃えるためのスケール定数
  `1.4826` を掛ける流儀があるが、本サービスは **生の中央絶対偏差** を返す
  （定義式の通り、係数を掛けない）。系列間の比較は問題ないが、`mad` と `std_dev` の
  数値を直接比べる際は分布仮定を踏まえて解釈すること。

---

## 3. 分位点（percentiles）

`p25` / `p50` (= `median`) / `p75` / `p90` / `p95` / `p99` を提供します。

### アルゴリズム

線形補間（linear interpolation between closest ranks）を採用しています。
これは NumPy 既定の `method='linear'`、Excel の `PERCENTILE.INC` と同じ手法です。

昇順ソート済み系列 `x₍₁₎ ≤ … ≤ x₍ₙ₎` と割合 `p ∈ [0, 1]` に対し、

1. 実数位置 `h = (n − 1) · p` を計算
2. 下側インデックス `i = ⌊h⌋`、上側インデックス `j = ⌈h⌉`、端数 `f = h − i`
3. `percentile(p) = x₍i+1₎ + f · (x₍j+1₎ − x₍i+1₎)`
   （`i` と `j` が等しい場合は `x₍i+1₎` そのまま）

### `iqr`

- `iqr = p75 − p25`（§2 [広がり] 参照）

### 縮退時の挙動

- **単一入力** (`n = 1`): 全ての分位点は `x₁`。したがって `iqr = 0`。
- **定数入力** (`x = (c, c, …, c)`): 全ての分位点は `c`。
- **空入力**: バリデーションで拒否される（`400`）。

---

## 4. 形状（shape）

### `skewness` (歪度, 母集団版)

- 定義: `g₁ = (1/n) · Σ ((xᵢ − μ) / σ)³`
  - `μ` は `avg`、`σ` は `std_dev`（母標準偏差）。
- **母集団版** を採用（Fisher-Pearson の標本補正 `√(n(n-1))/(n-2)` は掛けない）。
- 解釈:
  - `> 0`: 右裾が長い（大きな外れ値方向へ引きずられる分布）
  - `< 0`: 左裾が長い
  - `≈ 0`: 対称
- 縮退: 単一 = 0、定数 = 0（`σ = 0` のためゼロ除算ガードで 0 を返す）

### `kurtosis` (尖度, 母集団版)

- 定義: `g₂ = (1/n) · Σ ((xᵢ − μ) / σ)⁴`
- **母集団版・非 excess**（`− 3` の補正は行わない）。正規分布は 3 に近づく。
  ダッシュボード上で excess kurtosis と比較する場合は `kurtosis − 3` として扱うこと。
- 縮退: 単一 = 0、定数 = 0（`σ = 0` のためゼロ除算ガードで 0 を返す）

---

## 5. 外れ値カウント

### `outlier_count` (Tukey フェンス外れ値の個数)

- 定義: `x < p25 − 1.5·iqr` または `x > p75 + 1.5·iqr` を満たす `x` の個数。
- 意味: 分位点ベースで定義された **外れ値の件数**。`mad` が「頑健なばらつき (scale)」を
  返すのに対し、`outlier_count` は「外れ値の count」を返す。両者は補完関係。
- 縮退:
  - 単一・定数入力では `iqr = 0` となり、フェンスが 1 点に縮退するため
    条件を満たす値が存在せず 0。
  - `n = 2` などの少数入力でも定義通り評価される（統計的な意味は薄いが結果は返る）。

### 使い分けのヒント

- `std_dev` の平時値と比べ **`p95` が悪化** した場合、以下を併読すると原因を切り分けやすい:
  - `skewness` が同時に増加 → 分布そのものが右にシフトしている（例: ユーザー流入増による全体遅延）
  - `kurtosis` のみ増加 → 平均近傍は変わらず裾だけ重くなった（例: ごく一部の遅い経路）
  - `outlier_count` のみ増加 → 単発スパイク（例: GC 停止・ネットワーク瞬断）
- 頑健なばらつきの推定が欲しい時は `std_dev` ではなく `mad` を使う（外れ値耐性が高い）。
- スケールの異なる系列を横並び比較する時は `cv` を用いる（ただし正負混在系列には不向き）。

## 6. 参考: 上位レイヤでのフィールド対応

- `dashboard-bff` `GET /api/v1/dashboard/metrics/{name}/stats` は本ワーカーの
  一部フィールド (`count` / `min` / `max` / `sum` / `avg` / `p50` / `p95` / `p99` / `latest`)
  をパススルーする。ダッシュボード用に絞られた「クイックビュー」で、詳細な形状統計は
  ワーカーへ直接問い合わせる想定。
- `api-gateway` `GET /api/v1/metrics/{name}/stats` はサービス自身で軽量に計算した
  `count` / `min` / `max` / `sum` / `avg` / `latest` を返し、`p*` や `skewness` 等は
  含まない。分布形状を見たい場合は `dashboard-bff` あるいはワーカーへ問い合わせること。

## 7. 変更を加える際のガイド

- 新規の統計量を追加する時は、本ファイルの構成に沿って
  「定義 → 母集団/標本の別 → 縮退時の挙動 → 実務での解釈」を必ず記述する。
- README の Metrics Worker 表への追記も忘れず対応する（`docs/METRICS.md` への
  リンクをたどれば重複記述を減らせる）。
- 縮退時の挙動を変更する場合（例: 空入力を `null` で返すなど）は破壊的変更となるため、
  `CHANGELOG.md` にも記録する。
